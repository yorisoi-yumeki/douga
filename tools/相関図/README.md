# 相関図の自動生成

台本のデータから、本編で画面の右半分に出す相関図（L1）のPNGを作る。

**準拠：`docs/相関図仕様書.md` v3（決定#48〜#61）／方式：決定#62（全工程の自動化）**

```
  データ/01.json  ──┐
                    ├──→ 生成.py ──→ HTML ──→ 撮る.js ──→ 出力/01/*.png
  共通設定.json   ──┘      （検算）          （Chromium）
```

## 使い方

```bash
python3 生成.py 01        # 第1話だけ作る
python3 生成.py           # データのある話を全部作る
python3 生成.py 01 --表    # 台本に貼るページ割り表を出す（PNGは作らない）
```

出力は `出力/01/カット09_P4.png` のように**カット番号で名前がつく**ので、
CapCutではカットに合わせて画像を並べるだけでよい。
1つのカットで強調枠が動く場合は `カット02_P2_1.png` `..._2.png` と枝番がつく。

```
  大きさ  960×1080 を2倍で書き出す（1920×2160px）
          動画では右半分（x=960〜1920）に 960×1080 で置く
          2倍にしてあるのは、縮小したときに文字をきれいに見せるため
```

## ファイル

| ファイル | 中身 |
|---|---|
| `共通設定.json` | 配色・寸法・書体。**仕様書の数値をそのまま写したもの** |
| `データ/NN.json` | 話ごとのノードとページ割り（**作業④の成果物**） |
| `生成.py` | 検算とHTMLの組み立て |
| `撮る.js` | ChromiumでPNGにする |
| `書体/` | Google Fontsから取り寄せた書体（必要な字だけ・各14〜24KB） |
| `出力/NN/` | できあがったPNG |

**数値を変えるときは `共通設定.json` だけを直す。**`生成.py` に数値は書かれていない。
仕様書と食い違ったら、どちらが正かを決めて両方直すこと。

## 自動でやっている検算

生成の前に次を確かめ、1つでも外れると止まる。

```
  ❶ 幅の式        幅 ＝ (920 − 40×(n−1)) ÷ n が設定値と一致するか
                   ※ n=1 だけは式の例外（440px・中央寄せ）
  ❷ 神名の字数     幅 ÷ 48 に収まるか（2行になる行は2行ぶん）
  ❸ 小さい行の字数  幅 ÷ 文字サイズ に収まるか
  ❹ サブの字数     そのノードが置かれる最も狭い幅に収まるか
  ❺ 縦の高さ       帯を積み上げて1080pxに収まるか
  ❻ 帯の段数       3段以下か（仕様書3節）
```

## 書体

`Zen Kaku Gothic New`（神名・サブ）と `Zen Old Mincho`（漢字・読み）を
Google Fonts から取り寄せ、**HTMLに埋め込んでいる。**

```
  台本に出てくる字だけを取り寄せるので、1つ14〜24KB で済む
  一度取り寄せたら 書体/ に残るので、次からは通信しない
```

⚠ **ノードに新しい字が増えると、書体を取り寄せ直すために通信が要る。**

## 実装するときに見つかった、仕様書の誤り

### ❶ 退場ノードを「透明」にすると文字が読めない

仕様書0節は「塗りを抜いて輪郭だけ → 地に対して 6.19〜7.36 で読める」としているが、
**退場ノードは帯の中にあるので、背景は和紙ではなく帯 `#D6C39C` になる。**

```
  輪郭線と文字のコントラスト
                 対 和紙#FAF6EF    対 帯#D6C39C
    露草色          6.48             4.04  ✗
    琥珀色          7.01             4.36  ✗
    山吹色          6.82             4.25  ✗
    菖蒲色          7.36             4.59  ✓
    紅              7.29             4.54  ✓
    緑              6.19             3.86  ✗
                                     ↑ 6系統のうち4つが基準4.5を下回る
```

**対処：退場ノードの塗りを「透明」ではなく「和紙色 `#FAF6EF`」にした。**
これで仕様書0節の数値（6.19〜7.36）がそのまま成り立つ。
見た目も「穴が空いて紙が見えている」形になり、退場の意味に合う。

### ❷ 強調枠が外枠にはみ出す

```
  ノードの右端        940px （外周20 ＋ 使える幅920）
  ＋ すきま6 ＋ 太さ8
  強調枠の右端        954px
  外枠の内側          940px  ← 14px はみ出す
  キャンバスの右端    960px  （残り6px）
```

仕様書は外周20pxを「ノードの外側の余白」としか決めておらず、
**決定#61で強調枠（8px＋すきま6px）を足したときに、この14pxを数えていない。**

**対処：強調枠を外枠より前面に描く（`z-index`）。**
枠が全部見えることを優先した。枠が切れると「いま注目している対象」が伝わらないため。

## 縦書き（2026年11月28日に追加）

`共通設定.json` の `書字方向` を `縦書き` にすると、神名を縦1列にし、
その左に漢字・読みを縦に添える（縦書きは右の列から読む）。

```
  横書きの問題            縦書きにすると
  ┌────────┐          ┌──────┐
  │  大 八   │          │ お  大  │
  │  島 国   │          │ お  八  │   読む順番が
  └────────┘          │ や  島  │   一意に決まる
   大八島国？            │ し  国  │
   大島八国？            │ ま     │
   読む順番が決まらない    └──────┘
```

### ⚠ 段の高さは「1件ずつ」数える（2026年11月28日・文字が重なるバグ）

**長い名前のほうが背が低くなる逆転があるため、「段でいちばん長い名前」から
高さを決めてはいけない。**

```
  第14話 親の段
    ウガヤフキアエズ  8字 → 2列 → 4字×48 = 192px
    タマヨリヒメ      6字 → 1列 → 6字×48 = 288px  ← こちらが高い

  最長の名前（8字）から192pxに決めていたため、
  タマヨリヒメの6字が192pxに収まらず2列目に折り返し、
  **漢字「玉依毘売」の上に重なって表示された。**
```

**対処：ノード1件ずつ高さを出し、その最大を段の高さにする。**
さらに、描画するときの枠の高さも**そのノード自身が必要とする高さ**にする
（段の最大高さを当てると、短い名前がまた折り返す）。

### 長い神名は2列に折る（2026年11月28日）

縦書きの弱点は「長い名ほど縦に長くなる」こと。第11話で実測すると、
アメノオシホミミ（8字＝384px）とコノハナサクヤヒメ（9字＝432px）が
同じページに出るだけで、2段でも1,276pxになり収まらなかった。

```
  対処：1列6字を超える神名は2列に折る（共通設定.json の「1列の最大字数」）

    コノハナサクヤヒメ（9字）
      1列 → 432px        2列 → 240px（5字＋4字）
    縦書きは右の列から読むので、読む順番は変わらない
      右列「コノハナサ」→ 左列「クヤヒメ」
```

これで第11話の2段は 892px に収まる。

### 3段のページも収まる（2026年11月28日・前の記述を訂正）

> ⚠ **本書は一度「縦書きで3段は作れない」と書いたが、これは誤りだった。**
> 神名48pxを固定したまま、カード以外の余白を詰めれば収まる。
> 「できない」と書く前に、どこに何pxを使っているかを分解すること。

第11話の3段（1,410px）の内訳は次のとおりで、**カード以外が474px**あった。

```
  固定部分 474px               カード3枚 936px
    外周                20       アマテラス     5字×48 ＋枠88 = 328
    帯ラベルの余白      172       アメノオシホミミ 8字÷2列×48 ＋枠88 = 280
    親子の縦線          160       コノハナサクヤヒメ 9字÷2列×48 ＋枠88 = 328
    帯の下余白           42
    帯と帯のすきま       80
```

そこで**収まるまで段階的に詰める**ようにした（`共通設定.json` の `詰める段階`）。
**神名48pxはどの段階でも下げない。**

| 段階 | 変えるところ | 効果 |
|---|---|---|
| 0 | 標準（仕様書どおり） | — |
| 1 | 帯ラベルを帯の上から**左端の縦書き**へ | −112px |
| 2 | ＋ 親子の縦線 80→48・帯間 40→28・カードの余白を詰める | −148px |
| 3 | ＋ 1列5字まで（長い名は列を増やす） | 名による |
| 4 | ＋ 1列4字まで | 名による |
| 5 | ＋ 1列3字まで | 名による |

**話ごとに、全ページが収まるいちばんゆるい段階を自動で選ぶ。**
人が指定する必要はない（`--段階=N` で固定もできる）。

### 検証結果（縦書き・相関図576px＝映像70%・神名48px固定）

| ケース | 結果 |
|---|---|
| 1段のみ | ✓ 段階0 |
| 2段・第1話 | ✓ 段階0 |
| 2段・4兄弟（第14話） | ✓ 段階0 |
| 2段・9字を含む | ✓ 段階0 |
| 3段・短い名 | ✓ 段階2 |
| **3段・第11話の実物** | **✓ 段階4（958px）** |
| 3段・9字の神名を3個（人工の最悪ケース） | ✗ どの段階でも不可 |


## 神名を必ず1列にする（2026年11月28日）

`共通設定.json` の `名前は1列` を true にすると、神名を折り返さず必ず縦1列にする。
**読む順番の迷いが完全に消える代わりに、縦をたくさん使う。**

### 1列にしたとき、何字まで置けるか（相関図672px）

| 段数 | 役割の位置 | 余白 | 神名の上限 | 79ノードの何% |
|---|---|---|---|---|
| 1段 | どちらでも | 中 | 19字 | 100% |
| 2段 | 下 | 中 | 8字 | 96% |
| 2段 | **左列** | **強** | **9字** | **100%** |
| 3段 | 下 | 中 | 4字 | 39% |
| 3段 | **左列** | **強** | **5字** | **65%** |

```
  全79ノードが1列で収まるのは 2段まで。
  3段は5字までしか置けない（＝35%のノードが入らない）
```

### 成立する3パターン

| | 構成 | 段階 | 結果 |
|---|---|---|---|
| **1** | 2段 ＋ 役割を名前の左 | 2 | ✓ 全ノード1列 |
| **2** | 祖母を帯のラベルに格下げして2段 | 2 | ✓ 全ノード1列 |
| **3** | 3段 ＋ 長い名を5字に短縮（オシホミミ／サクヤヒメ） | 6 | ✓ 全ノード1列 |
| ✗ | 2段 ＋ 役割を下 | — | ✗ 1,084px（4px超過） |

```
  役割を下に置くと、2段でも入らない。
  1列を保証するなら、役割は必ず「名前の左」に置くこと
```

### 役割は「枠に重ねるタグ」にする（2026年11月28日）

**カードはもともと上余白16pxを持ち、その上には親子線の空間（44px）がある。**
タグを枠線にまたがせれば、この既にある空間を使うので**縦の追加がゼロ**になる。

```
          ┌─ 親子線の空間（44px・もともと空いている）
  ┌──┤降臨を辞退├──┐  ← タグが枠線をまたぐ
  │   ↑ 枠の外15px      │
  │   ↓ 枠の内15px      │  ← カードの上余白16pxに収まる
  │  天 ア              │
  │  忍 メ              │
  │  穂 ノ              │
```

| 役割の置き方 | 縦の追加 | 第11話2段 |
|---|---|---|
| カード下に横書き | +52px | ✗ 入らない |
| カード内の上タグ | +32px | ✗ |
| カードの外・帯の中 | +32px | ✗ |
| 左に列を足す | 0px | ✓（ただし文字が3列に増える） |
| **枠の上辺にまたがせる** | **0px** | **✓ ★推奨** |
| 枠の下辺にまたがせる | +15px | ✓ |
| 枠の左辺にまたがせる（縦書き） | 0px | △ 隣のカードと近い |

```
  枠に重ねると、縦のコストゼロのまま
    ・全79ノードの神名が1列に収まる（折り返しなし）
    ・カードの中は「名前＋漢字」の2列だけ。文字が増えない
    ・役割は色が反転するので、名前と混ざらない
```

## ⚠ 帯の下段は「兄弟」ではない（2026年11月28日・設計の穴）

**帯は「同じ世代」を示すもので、「兄弟」ではない**（決定#52・#53）。
ところが親子線を下段の全員に引いていたため、**全員が兄弟に見えていた。**

```
  第11話の実際の関係（台本どおり）
    アメノオシホミミ → ニニギ        親子   ✓ 親子線
    ニニギ × コノハナサクヤヒメ        夫婦   ✓ 二重線
    サルタヒコ                     血縁なし（道案内の国津神）
```

**仕様書4節には「夫婦」と「親子」の2種類しか線がない。**
血縁でない関係（道案内・敵対・従者など）の描き方は未定義だった。

### 対処

ノードに `続柄` を持たせ、`"子"` のときだけ親子線を引く。
`"他"`（血縁なし）の描き方は `共通設定.json` の `血縁でない線` で選ぶ。

| 設定 | 見え方 |
|---|---|
| `なし` | 線を引かない。系統の色とタグだけで示す |
| `点線` | 幹から点線で結ぶ。「関わりはあるが血縁ではない」 |

```
  ⚠ 帯を分ける案（「地上で出会う神々」を別の帯に）は
    3段になるため縦が1,290pxになり、収まらなかった
```

**⚠ 作業④では、ノードごとに `続柄` を必ず書くこと。**
省略すると「子」として親子線が引かれ、事実と違う図になる。

### 色が同じ2人をどう見分けるか（2026年11月28日）

コノハナサクヤヒメとサルタヒコは**どちらも地上・土着（琥珀色）**。
台帳どおりで正しい（ともに国津神）。仕様書も「夫婦＝ピンク」案を
**「夫婦は関係であって系統ではない。色は系統専用にする」**として却下している。

```
  ニニギ（露草色＝天津神） × コノハナサクヤヒメ（琥珀色＝国津神）
    天の神と地の神が結ばれる ← 色が違うことに意味がある
  サルタヒコ（琥珀色＝国津神）
    同じ国津神だが血縁も婚姻もない
```

**2人を分けるのは夫婦線。ところがその夫婦線が40pxしかなく見えていない。**

```
  カードの高さ 460px に対し、夫婦線は向かい合う辺の間 40px だけ
  親子線（幹＋兄弟バー＋縦線80px）は目に入る長さが200px超
  → 夫婦だけが極端に弱い
```

`共通設定.json` の `夫婦の見せ方` で4通りから選ぶ。

| 設定 | 見え方 |
|---|---|
| `二重線` | いまの仕様（2px×2・すきま4px）。40pxしか見えない |
| `太い二重線` | 4px×2・すきま8px |
| `隣接` | 夫婦のカードのすきまを 40→12px に詰める |
| `囲い` | 夫婦2人を1つの枠（3px・角丸24px）で囲う |
