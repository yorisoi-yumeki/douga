## 2. ❶ 上限超過の3話をどうするか

> ## ✅ 解決済（2026年11月21日・決定#49・#50）
>
> **この節の選択肢A・B・Cは、どれも採られませんでした。**
> 「ノードを積み上げる」という前提そのものを廃止し（#49）、
> **場面ごとに図を入れ替える**方式に変えたため、上限超過という問題自体が消えました。
> 同時表示は最大6個・平均3.9個です。
>
> ```
>   旧前提  1話の終わりに、その話のノードが全部出ている   → 第10話 12個
>   新方式  その場面に要るノードだけ出す（役目が終われば消す） → 最大6個
> ```
>
> 下の検算（物理的な上限は5段15ノード）は、**280px固定・1行3個を前提にしているため
> もう当てになりません。** 現在の規格は `docs/相関図仕様書.md` v3 3節。
> 1節の「画面に出る合計」の列も、**ノードの台帳としては有効ですが、
> 同時表示数としては無効**です。


### L1の物理的な上限を検算した

**「最大8ノード」は仕様書の表に書かれているだけで、決定ログに根拠がない。**
一方、画面に物理的に入る数は計算できる。

```
  L1キャンバス 960 × 1080 px ／ ノード 280 × 150 px
  縦余白 40px ／ 外周 上下 20px ／ 1行あたり3ノードまで

  段数   必要な高さ                       ノード最大   1080pxに入るか
  1段     150 + 0  + 40 =   190px          3個         OK
  2段     300 + 40 + 40 =   380px          6個         OK
  3段     450 + 80 + 40 =   570px          9個         OK
  4段     600 +120 + 40 =   760px         12個         OK  ← 仕様書の「最大4段」
  5段     750 +160 + 40 =   950px         15個         OK
  6段     900 +200 + 40 = 1,140px         18個         オーバー
```

**つまり物理的な上限は 5段15ノード。** 仕様書の「最大8」は読みやすさの上限であり、
画面に入らないという意味ではない。

### 選択肢は3つ

| 案 | 内容 | 影響 |
|---|---|---|
| **A** | **まとめノードに畳む** | 第10話なら「アメノホヒ・アメノワカヒコ・シタテルヒメ・喪屋の神々」を**「失敗した使者たち」1ノード**に畳めば 12→9。もう一段畳めば8。**台本の相関図の記述を書き換える必要がある** |
| **B** | **上限を8→12に引き上げる**（4段のまま） | 物理的には入る。**ただし「8」にした読みやすさの根拠が決定ログになく、引き上げてよいかを判断する材料がない** |
| **C** | **話の途中でノードを入れ替える**（ページ割り） | 仕様では「退場は不透明度50%」で、消す運用がない。**仕様の変更になる** |

⚠ **どれも私の判断では決められない。** Bは「読みやすさの上限」を動かすことになり、
スマホ実機で8ノードと12ノードを見比べないと決められない。

## 3. ❷ 追加されないまま操作されているノード（4件）

台本の相関図の指示が、**その話で画面に出していないノードのサブタイトルや不透明度を
変えようとしている**箇所である。

| 話 | カット | 指示 | 問題 |
|---|---|---|---|
| **8** | カット13 | 「八十神のサブタイトルを『**退けられる**』に差し替え、不透明度50%に落とす」 | 八十神は**第7話で出したノード**。第8話のおさらいカット（カット2）はオオクニヌシとスサノオしか出していない |
| **8** | カット14 | 「ヤガミヒメのサブタイトルを『**子を置いて帰る**』に差し替え、不透明度50%に落とす」 | 同じ。ヤガミヒメも第7話のノード |
| **11** | カット7 | 「アメノウズメのサブタイトルを『**問いに行く**』に差し替える」 | アメノウズメは**第5話のノード**。第11話のおさらいカット（カット2）はアマテラスとアメノオシホミミだけ。カット9で夫婦線も引くので、**画面に出ていないと成立しない** |
| **14** | カット3 | 「トヨタマヒメのサブタイトルを『**海へ帰る／道を塞ぐ**』に差し替え、不透明度50%に落とす」 | トヨタマヒメは**第13話のノード**。第14話のカット2はウガヤフキアエズだけ |

**直し方は2つ。**

```
  ① おさらいカットに「再掲」として足す
       → ノード数が増える（第11話は8→9で上限超過になる）
  ② 操作するカットで「追加」と書き直す
       → 同じくノード数が増える
```

> ## ⚠ 2026年11月21日の訂正
>
> **上の「①②どちらでもノード数が増える」「第11話は8→9で超過する」は誤りでした。**
> 1節の「再掲」列は、**この4ノードをすでに数え込んでいます。**
>
> ```
>   第11話で台本が明示的に「追加／表示」するノード
>     アマテラス・アメノオシホミミ・ニニギ・三種の神器・
>     五伴緒・サルタヒコ・コノハナサクヤヒメ            = 7個
>   1節の表                        新規5 + 再掲3 = 8個
>                                                  ↑
>                        差の1個 ＝ アメノウズメ（この節の対象）
> ```
>
> 第8話（新規2＋再掲4＝6／明示4個）・第14話（新規7＋再掲3＝10／明示9個）も同じ構造です。
> つまりこの❷は**台本の書き方の不整合**であって、ノード数の問題ではありません。
> おさらいカットに「再掲」と書き足すだけで閉じます。
>
> なお**❶（上限超過）そのものも決定#49・#50で解消しました。**
> ノードは積み上げず場面ごとに入れ替えるため、同時表示数は最大6個です。
> 詳細は `docs/決定ログ.md` #48〜#54。

## 7. L3（全体系譜図）の縦方向の検算

仕様書3節は**横幅だけ**を検算している（440×4＋余白＝1920px ぴったり）。
**縦は検算されていなかった**ので、ここで引く。

```
  L3は全画面 1920 × 1080 px ／ ノード 440 × 100 px ／ 縦余白 20px
  表示は9行（仕様書1節）

  ノード  9行 × 100px        = 900px
  縦余白  8箇所 × 20px       = 160px
  ──────────────────────────
  小計                        = 1,060px
  1080px との差               =    20px  → 上下に振ると各 10px

  ⚠ 外周を左右と同じ20pxにすると 1,100px でオーバーする（−20px）
```

**9行は入るが、上下の余白は各10pxしか取れない。**
仕様書3節の「外周の余白 左右20px」は**上下について何も書いていない**ため、
左右と同じ20pxだと思って作ると収まらない。**L3の外周は上下10pxと明記すべき。**
